# RCA — "Application not found" from backend host digital-cards-ia.emergent.host

## Problem statement
The Next.js app (nextjs-fullstack-11, served at https://nextjs-fullstack-11.emergent.host and
custom domain https://digitalcardsia.com.br) is up, but every call it proxies/SSR-fetches to the
FastAPI backend at https://digital-cards-ia.emergent.host returns **HTTP 400, body "Application
not found"**. Result: admin login fails, every /c/{slug} returns 404. Worked earlier today.
Shortly before the outage the user **started then cancelled a backend redeploy** of the separate
"digital-cards-ia" project; this job also ran a Next.js redeploy around the same time.

## What I verified (read-only, scoped to THIS Next.js job only)
1. **This job is healthy and unchanged in a way that matters.**
   - describe_deployment_state: deployment_status=active, active_run_id=75b2a711-ea2d-45dc-861a-f693ca6bd801,
     run_status=success (completed 2026-10-15T03:18:44Z). preview_health_check GET / => 200, real
     Next.js HTML. Custom domains www.digitalcardsia.com.br + digitalcardsia.com.br: verified=true,
     ssl_status=active, DNS linked=true.
   - This job's own URL is `nextjs-fullstack-11.emergent.host`. The host `digital-cards-ia.emergent.host`
     is **NOT** in this deployment's domain list and is **NOT** this job's deployed_url.

2. **This job did NOT take over / reassign the backend hostname.**
   - No run of this job binds `digital-cards-ia.emergent.host`. A redeploy only builds this job's image
     and promotes it onto this deployment's own pods/host — it cannot unbind or claim another Emergent
     project's hostname. The ~03:03 / 03:15 Next.js redeploys overlapping the backend redeploy are
     coincidental in timing, not causal.

3. **Backend-URL secrets are present and functionally point at the backend host.**
   - list_secrets (active run): BACKEND_INTERNAL_URL and NEXT_PUBLIC_BACKEND_URL both present, is_empty=false.
   - The reported symptom (requests DO reach digital-cards-ia.emergent.host and get a 400 from its edge)
     confirms the env still routes to that host.
   - Note: byte-exact comparison via `equals` returned matches_expected=false for
     `https://digital-cards-ia.emergent.host` and for the trailing-slash / `/api` / `http://` variants.
     Secret values are never returned, so I cannot read the raw string. This difference is almost
     certainly cosmetic (trailing slash or path) and is NOT the cause — if the env were wrong/empty the
     failure would not be a 400 "Application not found" FROM that exact host. (REACT_APP_BACKEND_URL is a
     platform SYSTEM key set to this app's own URL, so its mismatch with the backend host is expected.)

## Root cause
`HTTP 400 "Application not found"` is the Emergent reverse-proxy/edge response for a hostname that has
**no active, promoted deployment bound to it**. The request reaches our edge but there is no live app
registered for `digital-cards-ia.emergent.host` to route to.

This matches the described trigger exactly: the **cancelled backend redeploy** of the separate
"digital-cards-ia" project left that deployment without a promoted/active run (undeployed / unbound /
paused), so its hostname no longer resolves to a running backend. The outage is **100% on the backend
project, not on this Next.js job.** This job is healthy; it is simply the victim of its upstream
dependency going dark.

## Scope limitation
The backend ("digital-cards-ia") is a separate Emergent project. All my tools are scoped to THIS job
(nextjs-fullstack-11), so I could not directly read the backend project's deployment status, runs, or
whether it is undeployed vs paused vs deleted. That must be confirmed in the backend project's own
Deployment panel. Everything above about the backend state is inferred from the edge's "Application not
found" 400 plus the reported cancelled-redeploy trigger.

## Exact steps to restore the backend host
1. Open the **digital-cards-ia** project (the FastAPI/MongoDB backend) in Emergent → Deployment panel.
2. Check its status. Expect: no active/Live run, or a run stuck "failed/cancelled" from the cancelled
   redeploy. The green "Live" dot for digital-cards-ia.emergent.host will be absent.
3. **Redeploy** that project (or **Rollback** to its last known-good run) so a run reaches `promote` and
   the hostname `digital-cards-ia.emergent.host` rebinds to live pods.
4. Verify the backend is live BEFORE testing the frontend:
   `GET https://digital-cards-ia.emergent.host/api/public/demo` should return 200 (not 400
   "Application not found").
5. Once the backend is live again, this Next.js app recovers automatically — no redeploy of this job is
   required. The /api/* rewrite and /c/{slug} SSR will start resolving immediately.
